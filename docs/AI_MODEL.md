# لایه هوش مصنوعی — یادگیری رفتار قیمت

## ایده کلی

برخلاف موتور SMC/ICT که بر اساس **قوانین صریح از پیش تعریف‌شده** (Order Block، FVG، BOS/CHOCH و...)
کار می‌کند، لایه‌ی هوش مصنوعی یک مدل طبقه‌بندی است که مستقیماً از **رفتار تاریخی قیمت**
یاد می‌گیرد چه شرایطی معمولاً به حرکت صعودی/نزولی/خنثی منجر می‌شود — بدون اینکه قوانین SMC
را بداند.

```
قیمت تاریخی → اندیکاتورها/کندل‌ها → ویژگی‌های عددی (Features)
                                            │
                          برچسب‌گذاری Triple-Barrier (رفتار واقعی آینده قیمت)
                                            │
                              مدل یادگیری ماشین (GradientBoosting/RandomForest)
                                            │
                    پیش‌بینی احتمال صعودی/نزولی/خنثی برای کندل جاری
```

## برچسب‌گذاری (Triple-Barrier)

برای هر کندل، دو سطح فرضی (بر اساس ATR) تعریف می‌شود: یک سقف (شبیه TP) و یک کف (شبیه SL).
سپس تا `max_horizon_bars` کندل بعد بررسی می‌شود کدام سطح زودتر لمس می‌شود:

- سقف زودتر لمس شد → برچسب `+1` (رفتار صعودی)
- کف زودتر لمس شد → برچسب `-1` (رفتار نزولی)
- هیچ‌کدام تا پایان افق → برچسب `0` (خنثی)

این یعنی مدل چیزی را یاد می‌گیرد که **مستقیماً قابل معامله** است، نه صرفاً جهت قیمت.
پیاده‌سازی: `src/ml/labeling.py`

## ویژگی‌ها (Features)

۲۰ ویژگی عددی از بازده‌های اخیر، RSI، MACD، ATR نرمال‌شده، ADX، پهنای باند بولینگر،
فاصله تا EMA200، جهت SuperTrend، و نسبت‌های بدنه/سایه‌ی کندل ساخته می‌شود — همه فقط از
داده‌ی گذشته (بدون نشت اطلاعات آینده). پیاده‌سازی: `src/ml/feature_engineering.py`

## مدل

پیش‌فرض: `GradientBoostingClassifier` (یا `RandomForestClassifier`) از scikit-learn.
تقسیم train/test **زمانی** است (نه تصادفی) — یعنی مدل روی بخش قدیمی‌تر آموزش می‌بیند و
روی بخش جدیدتر تست می‌شود، شبیه شرایط واقعی معامله. پیاده‌سازی: `src/ml/model.py`

## استراتژی‌های قابل استفاده

- **`AIStrategy`** (`src/strategy/ai_strategy.py`): فقط بر اساس خروجی مدل سیگنال می‌دهد.
- **`EnsembleStrategy`**: «شبکه‌ی ادغامی» — ترکیب SMC + AI:
  - حالت `agreement`: سیگنال فقط وقتی صادر می‌شود که **هر دو** موتور (قوانین SMC و مدل AI)
    در بازه‌ی زمانی نزدیک هم‌جهت باشند → کمترین تعداد سیگنال، بالاترین اطمینان.
  - حالت `any`: سیگنال هرکدام از دو موتور پذیرفته می‌شود → بیشترین تعداد سیگنال.

## آموزش مدل

### از داشبورد (ساده‌ترین روش)
در داشبورد Streamlit، موتور تحلیل را روی «هوش مصنوعی» یا «ادغامی» بگذارید و روی
دکمه‌ی **«آموزش مدل روی داده فعلی»** بزنید. مدل بلافاصله روی داده‌ی همان لحظه
(نمونه/CSV/Twelve Data) آموزش می‌بیند و برای بقیه‌ی جلسه در حافظه می‌ماند.

### از خط فرمان (برای آموزش دائمی روی حجم داده بزرگ‌تر)
```bash
python scripts/train_model.py --csv data/your_large_history.csv --out models/xauusd_model.joblib
```
یک مدل از پیش آموزش‌دیده (روی داده نمونه) از قبل در `models/xauusd_model.joblib` قرار دارد
تا حالت AI/ادغامی بدون نیاز به آموزش دستی هم کار کند.

## ⚠️ محدودیت‌های صادقانه (مهم — حتماً بخوانید)

1. **خطر Overfitting**: در آزمایش با داده نمونه‌ی شبیه‌سازی‌شده، دقت آموزش حدود ۹۵٪ ولی دقت
   تست حدود ۵۰٪ بود — یعنی مدل بخشی از الگوهای تصادفی داده‌ی آموزش را حفظ کرده، نه یک الگوی
   واقعی تعمیم‌پذیر. این با داده‌ی **تاریخی واقعی طلا** (نه شبیه‌سازی‌شده) و حجم بیشتر (چند سال،
   نه ۲۰۰۰ کندل) بهتر می‌شود، اما همچنان باید با احتیاط دید.
2. **داده مصنوعی محدودیت دارد**: داده‌ی نمونه‌ی پیش‌فرض یک random-walk شبیه‌سازی‌شده است که
   الگوی واقعی بازار ندارد؛ مدل روی آن نمی‌تواند بهتر از یک حدس آگاهانه عمل کند. برای نتیجه‌ی
   واقعی، مدل را روی داده‌ی واقعی XAUUSD (از MT5 یا Twelve Data، چند سال کندل ساعتی) آموزش دهید.
3. **بدون Walk-Forward Validation**: نسخه‌ی فعلی فقط یک تقسیم train/test ساده دارد. برای استفاده‌ی
   جدی، باید Walk-Forward (آموزش مجدد دوره‌ای روی پنجره‌ی غلتان) اضافه شود تا drift بازار پوشش
   داده شود — این در فهرست کارهای آینده است.
4. **این توصیه مالی نیست**: خروجی مدل صرفاً یک احتمال آماری بر پایه‌ی الگوهای گذشته است، نه
   تضمین حرکت آینده. همیشه با مدیریت ریسک (Stop Loss، حجم مناسب) استفاده شود.

## نقشه راه توسعه‌ی این لایه (پیشنهادی برای آینده)

- افزودن ویژگی‌های مبتنی بر نواحی SMC (فاصله تا نزدیک‌ترین Order Block/FVG فعال) به بردار ویژگی
- Walk-forward retraining خودکار (مثلاً هفتگی) روی داده‌ی تازه
- امتحان مدل‌های دنباله‌ای (LSTM/Transformer) روی توالی خام کندل‌ها به‌جای ویژگی‌های دستی
- Cross-validation زمانی (Time Series Split) به‌جای یک تقسیم ساده برای تخمین دقیق‌تر عملکرد
- ثبت خودکار عملکرد مدل در طول زمان (Model Monitoring) برای تشخیص افت کیفیت (drift)
